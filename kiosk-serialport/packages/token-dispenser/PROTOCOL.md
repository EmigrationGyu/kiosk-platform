# TD-200 토큰 디스펜서 — 통신 프로토콜

가상 장치다. 실물 벤더 프로토콜은 공개할 수 없어, **같은 구조·같은 난이도**의 규약을
새로 정의했다. 상위 계층(FSM·뮤텍스·파서·probe)은 실제 제품 코드 그대로다.

하드웨어 없이 돌려보려면 루프백 구현을 쓴다 — `@serial/Port` alias 참고.

## 프레이밍

```
STX │ CMD(2~3B ASCII) │ DATA(가변) │ ETX │ BCC
```

`BCC` = STX 다음부터 ETX 까지의 XOR. 응답은 `ACK`/`NAK` 후 본문이 따라온다.

## 명령

| 코드 | 뜻 | 응답 |
|------|-----|------|
| `S4` | 상태 조회(4니블) | `SR` + 4바이트 |
| `S3` | 상태 조회(3니블) | `SR` + 3바이트 |
| `T1` | 토큰 1장 게이트까지 방출 | 상태 |
| `T2` | 게이트 토큰 → 반환함 | 상태 |
| `T3` | 게이트 토큰 → 호퍼(재사용) | 상태 |
| `P4` | 게이트 직전 대기 위치까지 | 상태 |
| `P6` | 중간 센서까지 | 상태 |
| `Z0` | 리셋 | 상태 |
| `V0` | 펌웨어 버전 | 문자열 |
| `F0`/`F1` | 자동/명령 급지 모드 | ACK |

## 상태 바이트

니블 4개를 각각 `0x30 + nibble` 로 실어 보낸다. 유효 범위는 `'0'`(0x30) ~ `'?'`(0x3f).
한 니블에 플래그가 겹치면 `: ; < = > ?` 가 나온다 — **ASCII hex 가 아니다.**
(`'C'`=0x43 을 값 0xC 로 읽으면 안 된다.)

| 니블 | bit | 뜻 |
|------|-----|-----|
| 1 | 15~12 | 반환함 만참 · 명령 불가 · 호퍼 만참 · 호퍼 임박 |
| 2 | 11~8 | 방출중 · 회수중 · 방출오류 · 반환오류 |
| 3 | 7~4 | 잼 · 겹침 · 잔량 임박 · 소진 |
| 4 | 3~0 | (미할당) · 호퍼출구 센서 · 중간 센서 · 게이트 센서 |

## 상태가 곧 FSM 의 정의역

어느 조합이 "진행 중"이고 어느 조합이 "종착"인지는 장치가 알려주지 않는다.
그 판정은 `src/fsm/transitions.ts` 가 소유하며, **단일 스냅샷으로 구분되지 않는 종착**
(게이트가 비었다 = 아직 안 나왔다? 이미 가져갔다?)은 직전 폴 상태를 요구하는
`needsPrev: true` 전이로 표현된다. 타입이 그 의존을 강제한다.
